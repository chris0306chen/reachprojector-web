# Projector Sample Acceptance Checklist for Business Buyers

Before approving a projector sample for a bulk order, agree what the sample must demonstrate, verify its exact identity and evaluate it in the intended setup. Record the conditions, observations and unresolved issues. Your approval should name the accepted configuration and explain which requirements remain subject to further checks.

## Agree the requirements before the sample arrives

A sample review is more useful when both parties know what counts as an acceptable result. Start with the application, intended image size, installation position, signal sources and required accessories. Our [projector RFQ checklist](/en/guides/projector-rfq-checklist-for-business-buyers) helps assemble that brief.

For each requirement, record a method, expected result and person responsible. For example, a meeting-room buyer could require readable text from an agreed presentation file at the normal seating positions, using the intended laptop and signal path. The buyer should specify the room lighting, image size and viewing positions before the check.

This is a proposed acceptance method, not a universal image-quality standard. If the contract requires a measured brightness or other laboratory result, agree the measurement procedure, equipment, operating settings and acceptance limits separately.

## Identify the sample and supplied configuration

Record the model, regional version, serial number and firmware version where available. Photograph labels and list the lens, remote, power cord and other supplied accessories. Compare these with the agreed sample specification.

Consult the exact manual for available information screens. For example, the [BenQ EH600 manual](https://esupportdownload.benq.com/esupport/PROJECTOR/UserManual/EH600/UM_EN_200806100914.pdf) describes detected input resolution and serial-number information. Menu names and available fields vary by model; do not assume every projector exposes the same information.

Keep identity checks separate from document checks. Request the documents specified for the project and ensure their model references match the proposed shipment. Receiving a document is not, by itself, verification of its validity or suitability for a destination.

## Reproduce the planned installation and signal path

Use the intended screen size and a documented placement. Follow the exact model's mounting, power and ventilation instructions. Record the source device, operating system where relevant, adapter, switcher or receiver, cable and projector input.

Manufacturer manuals provide the starting point for setup. The [Epson PowerLite EB-L520U series guide](https://files.support.epson.com/docid/cpd6/cpd61218/helpcontents.html) includes test-pattern, image-source and installation-setting instructions for the listed models. Use the corresponding documentation for your actual sample.

Check the complete signal path you plan to deploy. A direct laptop connection demonstrates that particular connection; it does not document performance through a different switcher, cable run or conferencing system. If an accessory is unavailable, mark that check as pending instead of recording a pass.

## Record observations against a shared checklist

The following table is a planning template. Replace the suggested methods and expected results with the requirements agreed for your project. No row below represents an actual test result.

| Requirement | Suggested method | Expected result to agree | Observation / evidence | Disposition |
|---|---|---|---|---|
| Model and region | Compare labels, menus and order specification | Agreed SKU and version | To record | Not checked |
| Accessories | Inventory package contents | Agreed item list | To record | Not checked |
| Placement | Set up at planned distance and image size | Fits documented installation limits | To record | Not checked |
| Presentation image | Display agreed files and patterns | Buyer-defined readability and image criteria | To record | Not checked |
| Signal sources | Run each intended device through the planned path | Agreed resolution and stable operation | To record | Not checked |
| Audio, if required | Check the planned audio path | Agreed routing and controls function | To record | Not checked |
| Control, if required | Exercise documented commands or integration | Agreed operations function | To record | Not checked |
| Operating scenario | Run the agreed usage sequence and duration | Buyer-defined operating criteria | To record | Not checked |
| Project documents | Match requested documents to model and scope | Required review completed by responsible party | To record | Not checked |
| Service arrangements | Review the written proposal | Agreed responsibilities and escalation contact | To record | Not checked |

Use clear dispositions: pass, fail, pending or not applicable. Explain every exception. For subjective observations such as audible fan noise, record the picture or power mode, room conditions and observer position. Do not convert a subjective impression into an unsupported numeric specification.

## Resolve exceptions before approving the configuration

Create an issue record with the requirement, observed result, evidence, owner and proposed resolution. Where a change is made, record what changed and which checks were repeated. A firmware update, different adapter or substitute lens should appear in the record rather than disappearing into an informal conversation.

If an unresolved issue is accepted, state its scope in writing. For example, approval for one signal source does not imply approval for an untested source. Keep the acceptance record specific enough for the buyer and supplier to identify the same configuration later.

## Separate sample approval from bulk shipment acceptance

A working sample is evidence about that sample under the recorded conditions. It does not establish the condition of every unit in a future shipment. Agree the required bulk configuration, treatment of substitutions, inspection arrangements and handling of discrepancies in the order documents.

The sample record should capture:

- Sample identity and configuration.
- Test date, reviewer and environment.
- Agreed requirements and recorded results.
- Open issues and accepted exceptions.
- Exact scope of approval and any remaining conditions.

### How long should the sample run?

Choose a duration and operating sequence that reflect the intended application, within manufacturer instructions. There is no single duration proposed by this checklist for every model and project. A reliability qualification requires its own agreed procedure.

### Does sample approval verify certification?

No. Functional checks and document verification are separate activities. Identify who will review required documentation for the specific model and destination.

### What should we send when requesting a sample?

Send the application, intended quantity, destination, installation constraints, required sources and your proposed acceptance criteria. Include any known integration requirements so the sample configuration can be defined clearly.
